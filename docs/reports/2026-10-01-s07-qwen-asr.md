## Принятое офлайн-поведение

1. **Выбор Qwen 0.6B/1.7B без подмены.** `qwen-local` выбирает `Qwen/Qwen3-ASR-0.6B` или `Qwen/Qwen3-ASR-1.7B` в разных каталогах. Корень/cache/revision разрешаются из `VOICEOVER_QWEN_ASR_*`, затем `[asr.qwen_local]` settings, затем legacy root с предупреждением. Unknown ID, неподходящий Hugging Face snapshot/ревизия и отсутствующие веса отклоняются до загрузки и без скачивания. В момент проверки выбранной модели resolver фиксирует канонические пути весов, ForcedAligner и cache; `from_pretrained` получает эти пути, receipt сообщает именно допущенные path/revision. Перенаправление symlink alias до или во время load не меняет загружаемую модель; следующая операция после смены alias/root/cache/aligner/revision fail-closed. Известное ограничение: нет OS-level fd/inode защиты от замены **самого канонического каталога**.
2. **Явный runtime.** `--runtime python` и `--runtime audio-cpp` не переключаются друг на друга при ошибке. `auto` сохраняет документированный env-driven выбор; preflight проверяет именно выбранную Python-модель либо закреплённый audio.cpp inventory до извлечения long-form. Текущий audio.cpp Qwen inventory поддерживает только 0.6B; запрос 1.7B на нём отклоняется до invocation. Whisper/Nemotron/audio.cpp и legacy CLI проверены регрессиями, а не live inference.
3. **Длинное аудио.** Один provider instance обслуживает последовательно bounded чанки. `source_sha256` до extraction и после последнего чанка обязаны совпасть, извлечённые WAV чанки получают отдельный `output_sha256`; изолированное изменение исходника fail-closed. Фрагменты обязаны совпадать по provider, model, runtime, model revision/path. Технические `coverage_*`/overlap остаются только в `execution.long_form`, а не выдаются за речевые времена. Text-only сегменты имеют `start_s/end_s = null`; word-сегменты ограничены реально удержанными после dedup словами. Времена provider-сегментов без слов сохраняются лишь при `native|forced` origin, без input overlap и при доказуемом соответствии текста. Несогласованные origin/weights/path отклоняются.
4. **SQLite и FTS5.** `transcribe` сохраняет текст отдельно в `text_sources`, а в run snapshot — `observed_spans` с origin, unit `ms`, effective model/path/revision, UUID **именно этого** `asr_transcript`, SHA-256 его точного текста и целочисленными observed char/ms span. История сравнивает hash исходного аудио из long-form receipt с фактически захешированным source artifact до commit; несовпадение откатывает run с фиксированным persistence error без повтора ASR, публичный transcript остаётся у вызывающего. Производный FTS индекс принимает время только при точном совпадении run/kind/origin/source UUID/text hash и когда **каждый речевой символ** поискового чанка покрыт наблюдаемыми span; иначе `start_ms/end_ms = null`. Offline rebuild получает те же времена из SQLite без модели/сети. Другой текст того же run, даже буквально равный транскрипту, не наследует тайминг. Публичный `transcribe --json` сохраняет прежние `start_s/end_s`.

## Fail-first и регрессии

- До исправления были красными тесты подмены 1.7B через alias во время `from_pretrained` и **после admission, до load**, перенаправления ForcedAligner/cache и повторного вызова после замены; на принятых байтах focused Qwen/ASR/history/search **201 passed**.
- Отдельные красные проверки выявили A/B расхождение source SHA между long-form и history, наследование времени вторым идентичным `asr_transcript`, ошибочные акустические span при `chunked` origin, а также кросс-ролевой/частично нетаймированный FTS диапазон. Положительный сценарий проверяет совпавший source hash и UUID, отрицательный сохраняет transcript при отказе записи, не оставляя завершённый run.
- ASR long-form подтверждён только синтетическими chunk/result fixtures; реальные Qwen веса, Torch/qwen_asr runtime и audio.cpp inference на этом Mac не запускались. Моки не измеряют WER/точность, качество, скорость или акустическое происхождение настоящих ответов.
