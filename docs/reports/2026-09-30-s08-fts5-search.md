## Что реализовано

### Схема (migration v3, аддитивная)

`add_search_chunks` добавляет производный слой поверх неизменённых канонических
таблиц: `search_chunks` (единица FTS с source/part/artifact/role/offsets/text/
hash/ms/chunker_version), `search_fts` (FTS5 `unicode61`, зеркало с общим
`rowid`), `search_index_state` (chunker version + последняя сборка) и
`search_index_pending` (источник, чью производную запись не удалось записать).
`text_source_uuid` намеренно nullable: label-чанк принадлежит прогону, а не
текстовому источнику. FK `run_uuid`/`text_source_uuid` с `ON DELETE CASCADE`
вместе с trigger на удаление chunk гарантируют, что даже FTS-термы не переживут
каскадное удаление канонического прогона/текста.

### Производная форма и чанкинг (не канонический текст)

- `normalize_search_text`: `ё → е` и регистр, **только** для FTS-колонки и запроса;
  `text_sources.content` не меняется, а сниппет срезан из оригинала через явную
  карту offset'ов.
- `split_text_chunks`: ~1200 Unicode-символов с перекрытием до 150 по границам
  абзацев/предложений; чанкинг помечен `CHUNKER_VERSION`, не трогает TTS-части,
  аудио и стоимость.
- `build_match_expression`: запрос превращается в `AND` из закавыченных
  нормализованных слов-токенов, поэтому кавычки, дефисы, пунктуация и SQL-подобный
  ввод не становятся ни MATCH-оператором, ни SQL.

### Поиск

`search_lexical` — один SQL с `bm25(search_fts) ASC` и всеми фильтрами
(`role`, `kind`, `run`, `operation`, `provider`, `since`, `until`) **в `WHERE` до
`LIMIT`**. Роли: `label`, `speech` (сценарий), `asr` (ASR и verify транскрипты),
`directions`; приватный `asr_context` не индексируется. Default scope —
speech+asr+label, `directions` — opt-in. Результат несёт source/part/artifact
ссылки, `snippet`, `provider`/`model`, `created_at` и `audio` с `availability`;
нативный/платный ASR-транскрипт ссылается на `asr_source_audio` (в старой платной
истории — на канонический identity-snapshot без выдуманного artifact UUID).
Завершённый TTS ссылается на финальное аудио, незавершённая часть — только на
**своё** аудио или `null`; удалённый после сохранения локальный файл возвращается
как `missing`, не стирая историю. Нуль-дополненный `--until YYYY-MM-DD` включает
весь названный день, фильтр остаётся до `LIMIT`.

### Немедленная индексация и recoverability

`HistoryRepository.add_text_source` (и `create_run` для короткой метки) ставит
источник в очередь, а `transaction()` после **outermost COMMIT** выполняет
производную запись best-effort. Сбой индекса логируется предупреждением, источник
помечается `search_index_pending`, а канонический текст остаётся закоммиченным;
`index build` детерминированно и идемпотентно добирает пропущенное из SQLite.
Для label-only прогона без текстового источника `index status` считает
`labels_missing`, не объявляет индекс полным и направляет к тому же `index build`.
Rollback очищает очередь.

### CLI

- `voiceover search QUERY --mode lexical [--scope] [--limit] [filters] --json`.
- `voiceover index status|build|rebuild [--json]`.
- `--mode semantic|hybrid` → exit `2`, `SEARCH_MODE_DEFERRED`, без пустого
  результата. Embedding/vector зависимостей не добавлено.
- `index status` честно отдаёт `sources_indexable/indexed/pending/private_excluded/
  incomplete`, `label_runs/labels_missing`, `indexed_chunks`,
  `chunker_version`/`built_chunker_version`, `complete`, `needs_rebuild`;
  неполный импортированный корпус, старые тексты после v2→v3 upgrade или
  пропущенная метка → `complete: false`; `search` предупреждает о таком corpus gap,
  несохранённом тексте и необходимости пересборки при смене версии chunker.
  Повторные build/rebuild не считают приватный `asr_context` проиндексированным;
  `provider/model` проецируются из уникальной подходящей типу текста/части
  попытки либо честно равны `null` при неоднозначности.
- `build`/`rebuild` — одна `BEGIN IMMEDIATE` транзакция: сбой оставляет прежний
  индекс. `status` читает read-only и не создаёт sidecar.

записи → pending + сохранённый текст → rebuild восстанавливает, атомарный rollback
пересборки, CLI JSON/exit/help. Четыре новых fail-first случая по review:
реальный native-ASR save → source-audio fallback; inclusive `--until` на том же
дне через SQL и CLI; удаление файла после сохранения → `missing` без потери
текста; сбой индекса label-only прогона → `labels_missing`, `complete: false`,
предупреждение и восстановление `index build`. После второго BLOCK-review новые
fail-first случаи: populated v2→v3 upgrade с частично индексированным корпусом
→ предупреждение до `index build`; paid timing fake-POST → durable source artifact
до POST и snapshot-only fallback старых платных прогонов; две native части с
аудио только первой → у второй `audio: null`, после завершения приоритет final;
удаление канонической записи → никакого осиротевшего FTS-терма; strict ISO date,
неполные тексты и mismatched chunker version → честные предупреждения.

## Границы и что не доказано

- **S09 deferred**: semantic/hybrid, embeddings, `sqlite-vec`, профили, кеш и
  hybrid RRF **не реализованы**; соответствующий `--mode` явно отклоняется.
- **ASR time ranges**: реальные span'ы не сохранены в текущем transcript-writer'е,
  поэтому `start_ms`/`end_ms` = `null`. Никакого пропорционального деления по
  буквам нет; когда span появится у writer'а, поле заполняется без новых
  guess'ов.
- **Live/listening**: реальный живой корпус, реальные аудиофайлы и человеческое
  прослушивание — `NOT_RUN`. Не заявлено.
- **Морфология/семантика**: точный лексический поиск; формы «модель» и «моделями»
  без дополнительной обработки не совпадают. Это не заявляется как morphological
  или semantic recall.
