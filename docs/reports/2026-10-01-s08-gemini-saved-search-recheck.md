# S08 — проверка поиска по сохранённым Gemini-пробам

Статус: локальная offline-проверка пяти настоящих сохранённых прогонов; **не** проверка нового оплаченного запроса, тарифа или multi-speaker-генерации. Исходные приватные SQLite находятся в пяти отдельных каталогах `/private/tmp/voiceover-gemini38-{probe.YtWtEF,probe2.lkK8r9,story.vV7p8J,dialogue.R7Obup,play.WtXAC2}/state/history.sqlite3`. Без указания соответствующего `VOICEOVER_HOME` обычный `voiceover search` их не объединяет и не видит.

## Что было обнаружено

В каждом DB были канонические `runs`, `parts`, `attempts`, `text_sources` и производные FTS5-чанки; произнесённые слова рассказа, диалога и спектакля находились офлайн. Но `search --scope directions` **не находил** настроение отдельных частей: конкретные инструкции сохранены в `parts.vibe_effective`, а S08 прежде индексировал только `text_sources`. Вместо этого находился общий стиль Polza по умолчанию, записанный в старых speech-parts снимках, хотя этот стиль **не передавался** адаптером провайдеру. Такую выдачу нельзя использовать как доказательство передачи инструкции.

## Исправление и воспроизводимость

Производные FTS5-чанки `directions` теперь создаются из непустых `parts.vibe_effective` с привязкой `part_uuid`, не смешиваются с обычным `--scope speech`, пересоздаются `index rebuild` и дозаполняются `index build`/после сохранения канонического текста. Старые неотправленные run-level стили исключаются из производного индекса при наличии speech-parts с заполненным `vibe_effective`; их канонические `text_sources` **сохранены** для целостности истории/native snapshot. `index build` также удаляет возможные старые `search_index_pending` для исключённых стилей; новые `--text`/speech-parts не сохраняют фиктивный стиль по умолчанию, а явные `--style-prompt`/`--style-prompt-file` с `--text` отклоняются до ключа/провайдера, вместо тихого игнорирования. Это правило относится к индексированию данных, а не к поддержке Gemini или доказательству услышанного настроения.

Перед offline-ремонтом все пять DB показывали по одному устаревшему style-чанку и `index status.complete=false`. `index build` выполнен для **каждого** каталога с запретом `socket.connect` в процессе; результат:

| DB | Удалено старых style-чанков | Найдено настроение `--scope directions` | Слова текста найдены | `complete` |
|---|---:|---:|---:|---|
| одиночный Kore | 1 | 0 (не задавалось) | да | true |
| одиночный Puck | 1 | 0 (не задавалось) | да | true |
| рассказ (2 части) | 1 | 1 | да | true |
| диалог (2 части) | 1 | 1 | да | true |
| спектакль (3 части) | 1 | 1 | да | true |

На более раннем этапе `index build` добавил 2/2/3 отсутствовавших per-part направления для рассказа/диалога/спектакля; повторный запуск идемпотентен. Слово старого фиктивного стиля больше не выдаётся в `directions`, слово из фактического настроения выдаётся в `directions`, но не в `speech`. Для каждого DB до/после ремонта сравнивались количества канонических `runs`, `parts`, `attempts`, `text_sources` и упорядоченные статусы/стоимости оплаченных attempts: **без изменений**. Индекс — только производный, приватные аудиофайлы не менялись.

Локальные проверки точных Python-байтов после двух исправлений по review: fail-first новых тестов, затем focused **93 passed**, полный `uv run --offline --frozen pytest -q -o addopts=''`: **2387 passed / 2 skipped**; Ruff lint PASS, Ruff format **193 files PASS**, mypy `--no-incremental` **92 source files PASS**, `git diff --check` PASS.
