### Exit codes (`docs/agent-cli-contract.md`)

`0` success · `2` invalid args · `10` missing dependency · `11` no ffmpeg/ffprobe · `20` no key · `30` provider/run error · `40` whisper error · `50` output error · `60` TTS quality failed.

### JSON stdout/stderr

- `--json`: stdout = ровно один JSON object (success или error), stderr = progress/warnings, exit code семантический.
- Error: `{"status": "error", "error": "...", "code": <int>}`.
- Ошибка argparse при `--json` → единственный JSON `{"status":"error","error":"Invalid command-line arguments","code":2}`, exit `2`.
- `--skip-existing` → `{"status": "skipped", ...}`.
- `--json` + `--json-events` несовместимы (exit `2`).

### `--format` и `--resume`

- Source `build_parser`: `generate --format` и `validate --format` — choice `["markdown", VOICEOVER_FORMAT, DIALOGUE_FORMAT, GEMINI_DIALOGUE_FORMAT]` (docs: `markdown`, `voiceover`, `dialogue`, alias `gemini-dialogue`), default `markdown`. То есть `--format` выбирает формат сценария.
- `--resume` — `action="store_true"` (boolean), default `false`.
- `concat --format` — отдельное перегруженное имя флага: choice `mp3|ogg`, default `ogg` (аудио, не сценарий).
- Alias: `--format gemini-dialogue` — compatibility alias формата `dialogue`; state/manifests пишут `format: dialogue`.

### Артефакты

`docs/agent-cli-contract.md`: `out/<run-id>/` содержит `manifest.json` (entry-point), `<run-id>-voiceover-<model>.mp3`, `<run-id>-voiceover-<model>.json`, `<run-id>.timings.json`, `<run-id>.srt`, `chunks/chunk_NN.mp3`, `chunks/chunks.json`. ## 11. Baseline логирования (code-intelligence snapshot, без live-прогона)

Граница доказательств: это статический снимок кода, а не проверенный live-лог. Реальные логи не запускались и не приводятся; секреты и приватные данные не публикуются.

- Селекторы (родительская code-intelligence сессия): Codebase `search_graph` → `src/voiceover_pipeline/run_state.py::GenerationLogger.event` и `src/voiceover_pipeline/cli.py::_emit_json_event`; Serena `find_symbol(GenerationLogger)` → форма строки `generation.log`; ast-grep перечислил call sites логгера в `cli.py`. Имена событий ниже подтверждены и прямым чтением `cli.py`.
- `generation.log` — текстовый файл. Формат строки: `utc_now()` + `LEVEL.upper()` + `event` + поля `key=value`. `None`-поля пропускаются; `\n` заменяется пробелом; значения с пробелами или пустые оборачиваются `json.dumps`. Централизованной очистки (redaction) нет.
- `generation.log` (текст) отличается от `--json-events` (NDJSON): `_emit_json_event` печатает `{"event": ..., ...}` только при `--json-events`.
- Наблюдаемые события `logger.event` в `cli.py`: `run_started(run_id, provider, model, chunks)`, `resume_rejected(reason)`, `chunk_started(chunk, id, file)`, `chunk_provider_response(chunk, id, generation_id)`, `chunk_retry(chunk, id, attempt, delay_sec, error)`, `chunk_state_saved(chunk, id, state)`, `concat_complete(output, duration_ms)`, `timings_failed(error)`, `run_complete(run_id, duration_ms)`; среди прочих также `resume_detected`, `state_replaced`, `chunk_trimmed`, `concat_started`, `concat_failed`, `timings_started`.
- Риск на момент snapshot: поля `error=str(e)` (например, в `chunk_retry`, `timings_failed`, `concat_failed`) могут содержать чувствительный текст, централизованной санитизации нет. Это не заявление о текущей очистке вывода; риск запланирован к отдельной задаче (P1 `GenerationLogger` в §2 плана).
- Регрессионное покрытие: `tests/test_generation_stability.py::test_generate_step_writes_state_and_log_after_each_chunk` проверяет запись `chunk_started`/`chunk_state_saved`; тест прошёл в полном прогоне (§12.3).
