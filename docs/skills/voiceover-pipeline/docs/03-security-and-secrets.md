# Безопасность и секреты: env-файл и API-ключи

> АГЕНТ: ЧИТАЙ ЭТОТ ФАЙЛ ЦЕЛИКОМ И СОБЛЮДАЙ ПРАВИЛА.
> Это критичный файл. Нарушение любого правила — ошибка навыка.

## Главное правило

**НИКОГДА не читай, не печатай, не парси и не копируй реальный `.env`.**
Даже чтобы проверить, есть ли там ключ.
Даже если пользователь просит «посмотри, правильно ли я вставил ключ».

## Что делает агент, а что пользователь

- Агент создаёт только **`.env.example`** с синтетическими placeholder-ами
  (не с реальными ключами) и убеждается, что `.env` указан в `.gitignore`.
- Агент **не создаёт и не копирует** `.env` через shell (`cp`, `Copy-Item`,
  `type`, `cat`) и не читает его.
- Реальный env-файл пользователь создаёт сам, вручную, вне инструментов агента,
  и вписывает в него свои ключи. Альтернатива — уже существующие переменные
  окружения процесса.
- **НИКОГДА не проси пользователя прислать API-ключ в чат.** Ключ не должен
  попадать в переписку, логи или команды.

## Порядок разрешения секрета

Когда команде действительно нужен ключ (генерация, проверка провайдера), значение
разрешается в одном порядке:

1. непустая переменная окружения процесса — приоритет; содержимое файла тогда не читается;
2. явный глобальный `voiceover --env-file PATH <command> ...` — проверяется
   только по метаданным как regular file;
3. `<call-time CWD>/.env` — для совместимости.

Поиска `.env` по родительским каталогам **нет**. Явный `--env-file PATH`
**заменяет** CWD-файл, а не дополняет его: если в явном файле ключа нет,
фоллбэка на `<CWD>/.env` не происходит. Отсутствующий, не-regular или
недоступный для проверки метаданных явный путь fail-closed с exit `20` **даже
если** в окружении есть пригодный ключ; сообщение не содержит ни путь, ни
значение. `help` не читает ключ и env-файл даже при заданном `--env-file`.

## Шаблон `.env.example`

Создай файл `.env.example` с безопасными mock placeholder-ами:

```env
# This is a template with synthetic placeholders. Do NOT commit a real env file.
# The user creates their own private env file outside the agent tools, or uses
# process environment variables.

OPENROUTER_API_KEY=sk-or-...xxxx
POLZA_API_KEY=pza_xxxxxxxxxxxxxxxx
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxx
X_AI_API_KEY=xai-xxxxxxxxxxxxxxxx
```

Не копируй этот шаблон в `.env` сам. Сообщи пользователю: «Создай приватный
env-файл вне инструментов агента и впиши в него ключи; либо задай переменные
окружения процесса.»

## Какие ключи нужны

Реальные имена переменных (значения агент никогда не читает и не печатает):

- **Polza (chat-audio + tts):** `POLZA_API_KEY` — начинается с `pza_`. Один ключ для обоих polza-провайдеров.
- **OpenRouter:** `OPENROUTER_API_KEY` — начинается с `sk-or-v1-`
- **Groq Whisper (timing):** `GROQ_API_KEY` — начинается с `gsk_`. https://console.groq.com/keys
- **xAI STT (timing):** `X_AI_API_KEY` — начинается с `xai-`. https://docs.x.ai
- **Qwen-local / Faster-Whisper:** ключи НЕ нужны (работают локально).

## Проверка через doctor

`doctor` — единственная команда, которая проверяет наличие ключа и сообщает
разрешённый путь:

```powershell
voiceover doctor --provider polza-chat-audio --json
voiceover doctor --provider openrouter-tts --json
```

- Смотри на `checks.env_file.path` (разрешённый явный путь или `<CWD>/.env`) и
  `checks.env_file.ok`, а также на поля `<provider>_key.ok` / `required`. Значение
  ключа `doctor` не печатает никогда.
- При непригодном явном `--env-file` `doctor` завершается с exit `0` и JSON
  `status: "success"`, но сообщает `checks.env_file.ok: false` и `workflow_ok: false`.
- Запускай `doctor` только в одобренном окружении; не запускай его против
  реального пользовательского окружения без явного разрешения.

Если `ok: false` и `required: true` — скажи пользователю, какой ключ добавить.
Если `required: false` — ключ для данного провайдера не нужен, это не ошибка.

## Дальше работай молча

После того как ключи на месте — не спрашивай о них снова. Если ключ исчез, CLI
сам упадёт с exit code `20`. `help` в ключах вообще не нуждается.

## Где ищется env-файл

Значение берётся из непустого окружения процесса, иначе из явного `--env-file`,
иначе из `<CWD>/.env` в текущем рабочем каталоге. Родительские каталоги не
просматриваются.

## Чего нельзя делать

- ❌ `cat .env` / `type .env` / `cp .env.example .env` / `Copy-Item .env.example .env`
- ❌ Читать, парсить или печатать `.env` любым инструментом
- ❌ Показывать содержимое `.env` или значение ключа в ответе или логе
- ❌ Просить пользователя выполнить `export POLZA_API_KEY=...` в терминале
- ❌ Коммитить `.env` или реальный env-файл в git
- ❌ Создавать `.env` с реальными ключами (только `.env.example` с placeholder-ами)
- ❌ Просить ключ повторно после того как `doctor` показал `ok: true`
- ❌ Угадывать, подбирать или придумывать ключи
