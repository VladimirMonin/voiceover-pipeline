# Журнал разработки — Voiceover Pipeline — 2026-08-16

## Короткий итог

За день проект прошёл от принятого generic local ASR к гибридной миграции
локальных non-Whisper моделей на runtime-neutral слой с первым драйвером
`audio.cpp`. Foundation принят и сохранён локальным commit; Qwen offline-срез
после содержательного отклонения исправлен и независимо принят на точном
незакоммиченном digest. Linux/CUDA-контейнер и модели подготовлены, но настоящий
50-кейсный Qwen live parity ещё не выполнен. После вопроса Владимира обнаружен
реальный пробел: текущий delivery route Linux-specific и не доказывает работу
Voiceover Pipeline на Windows; для Windows создан отдельный audit → native
implementation → package → family live gates → acceptance маршрут.

## Решения пользователя

- Локальные Qwen3-ASR, Nemotron 3.5 ASR, Qwen3-TTS и OmniVoice идут через общий
  runtime-neutral слой; `audio.cpp` — первый driver, а не публичный provider ID.
  Faster-Whisper и cloud providers остаются независимыми маршрутами.
- Windows должна работать нативно через проверенный package; Docker Desktop и
  WSL2 не могут быть обязательным пользовательским контрактом.
- Существенные исправления и acceptance stages планируются в Kanban, но мелкие
  1–2-строчные дефекты исправляются напрямую; плановые live/paid/model runs не
  объявляются выдуманными blockers.
- Ретроспектива не копирует Kanban: task ID нужен только для verdict, blocker,
  решения или точного handoff.
- На проект хранится один `docs/retrospectives/YYYY-MM-DD.md` за сутки; повторный
  запрос обновляет его на месте, индекс содержит одну строку, отчёт коммитится.

## Реальные проблемы

1. **Qwen live acceptance не завершён.** Нет 50/50 parity, пяти повторений,
   resource/stability/unload evidence и точного `LIVE_PASS`.
2. **Windows route отсутствует в продукте.** Upstream `audio.cpp` умеет native
   Windows CPU/CUDA/Vulkan и packaging, но VOP launcher, ZIP, DLL inspection и
   реальные Windows family runs ещё не существуют.
3. **Nemotron не принят.** Реализация есть, но прежний reject по exact wire
   semantics (`language`/prompt terminology route) не закрыт свежим review и
   live gate.
4. **Canonical plan отстал от исполнения.** В нём всё ещё стоит
   `implementation has not started`, а Windows correction/DAG не отражены.
5. **Рабочее дерево смешанное и грязное.** Принятые и непринятые изменения нельзя
   выдавать за один проверенный срез или коммитить общей массой.

## Ошибки и отменённые решения

- **SUPERSEDED:** Linux/CUDA и NVIDIA driver ранее формулировались как широкая
  граница поддержки. Exact-image CUDA smoke доказал, что проблема была в
  конкретном delivery/toolkit route, а не в Linux, GPU или model family.
- **SUPERSEDED:** Docker route рассматривался как достаточная общая поставка.
  Windows correction показала Linux-specific пути, mounts и protocol boundary;
  теперь Docker — один Linux route, а Windows требует native launcher/package.
- **SUPERSEDED:** root disk временно считался внешним блокером доставки моделей.
  Модели размещены на отдельном storage и проверены checksum; cache очищался без
  удаления пользовательских данных.
- Повторный Nemotron review на неизменённом rejected digest был бесполезным
  control-plane циклом и не дал новой acceptance evidence.
- Статус migration plan не обновлялся вслед за foundation, Qwen/Nemotron work и
  Windows correction; live Git/Kanban сильнее этой устаревшей строки.
