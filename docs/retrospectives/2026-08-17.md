## Решения пользователя

- Практический ASR acceptance требует распознанный текст и тайминги
  фраз/сегментов; word timings дополнительны. Ручная word-boundary разметка всех
  50 записей и отдельный fixture длиннее 180 секунд не входят в critical path.
- Linux использует exact CUDA-container route, Windows — native package с
  `audiocpp_cli.exe`; Linux/static evidence нельзя выдавать за Windows live proof.
- Плановый реальный или платный прогон, уже предусмотренный инструкциями, не
  является проблемой сам по себе. Обязательный platform security approval нельзя
  обходить.
- Один writer работает в общем дереве; мелкие 1–2-строчные дефекты исправляются
  прямо, без дублирования карточек и широкого повторного gate.
- Push выполняется только по отдельному явному запросу.

## Реальные проблемы

1. **Qwen live ждёт platform approval для `sudo -n docker`.** Это адекватная
   внешняя security boundary только Qwen live acceptance, а не дефект проекта и
   не повод менять проверенный production route.
2. **Nemotron live не имеет готового Linux production admission.** Нужны
   Nemotron-capable container/native transport, проверенный GGUF/model artifact
   и рабочий incumbent Python comparator. Это реальный внутренний пробел одной
   ветки; `WVM_ROOT` к нему не относится.
3. **Native Windows live не проверен.** Доступного Windows 10/11 x64 host с
   NVIDIA и настроенным native package route нет. Это внешний blocker только
   Windows ZIP/DLL/CUDA/model acceptance.
4. **Qwen3-TTS не принят после worker crash.** Два найденных дефекта ограничены
   cancellation registration и imports; новая карточка для них не нужна.
5. **Аппаратная нестабильность подтверждена множественными `SIGSEGV` Python/Node.**
   Это реальный риск control plane, но не абсолютный product blocker: продуктовые
   проверки проходят, работа продолжается одним тяжёлым процессом без durable
   monitor.
6. **Dirty tree требует scoped staging.** Это интеграционный риск, но не причина
   останавливать независимые ветки; `git add .` запрещён.

## Ошибки и отменённые решения

- **SUPERSEDED:** `WVM_ROOT unset` был указан как один из Nemotron live blockers.
  Канонический checkout существует; это обычный аргумент запуска, а не
  инфраструктурный пробел.
- **SUPERSEDED:** eager import `nagisa`/DyNet считался общей Qwen shutdown
  нестабильностью. Причина локализована и исправлена lazy admission без
  случайного downgrade зависимостей.
- Первый Nemotron contract передавал выдуманный request-side
  `prompt_dictionary` вместо exact `language`; повторный review неизменённого
  rejected digest зря потратил цикл. Исправленный manifest позже принят.
- Старый Qwen harness ошибочно требовал ручные word boundaries и отдельный
  `>180 s` fixture. Оба требования удалены из critical path.
- Два durable monitor после reproducible `SIGSEGV` не дали product evidence;
  третий не запускается.
- Статус «Qwen3-TTS выполняется» устарел после `SIGSEGV` worker: current truth —
  частичный непроверенный срез с двумя bounded defects.
- Плановые paid/local live runs и все board `blocked` нельзя автоматически
  трактовать как текущие аварии; verdict определяется инструкциями и прямым
  evidence.
