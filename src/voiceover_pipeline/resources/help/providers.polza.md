## Ключ

`POLZA_API_KEY` разрешается в порядке: окружение процесса (приоритет); затем явный `voiceover --env-file PATH ...`; затем `<CWD>/.env`. Явный `--env-file` заменяет CWD-файл. При обращении к ключу отсутствующий, не-regular или недоступный для проверки метаданных явный путь fail-closed (exit `20`, без пути и содержимого) даже при ключе в окружении; содержимое файла в этом случае не читается. Ключ используется для маршрутов `polza-chat-audio` и `polza-tts`. `doctor` тоже может прочитать `.env` для проверки наличия ключа и показывает путь `env_file.path`, но не значение ключа. `help` не читает `.env`, ключи и историю. Полный порядок — `voiceover help start.quick`.

## Зарегистрированные маршруты

`polza-chat-audio` — chat-completions с аудио в ответе; `polza-tts` выбирает
`/audio/speech` или асинхронный `/media` по модели. Список **текущих
зарегистрированных** моделей и голосов берите из CLI, а не из статической
таблицы справки:

```bash
voiceover list providers --json
voiceover list voices --provider polza-tts --json
voiceover generate --help
```

Голос можно указать явно или взять из сценария; приложение не подменяет
названный пользователем голос. `voiceover doctor --provider polza-chat-audio
--json` проверяет наличие ключа через приложение и может прочитать env-файл;
агент запускает его только в одобренном окружении. Ни `list`, ни `help` не
подтверждают фактический тариф, качество или доступность внешнего API.

## Границы, которые важно не переоценить

- **Live TTS-приёмка не выполнялась.** Реальных TTS POST и прослушивания не было; MIME/контейнер, голоса, применимый тариф и скорость не подтверждены. Source-level маршруты и офлайн-тесты — это `NOT_RUN` для живого TTS. Не заявляйте работоспособность, цену или качество модели по историческим примерам.
- **Candidate-маршрут Gemini 3.8 намеренно заблокирован.** Один разрешённый GET `/models` подтвердил Polza ID `google/gemini-3.8-flash-tts` и `google/gemini-3.8-flash-lite-tts`, но не endpoint, поле инструкции, голоса, контейнер и применимый тариф. Значение `tts_per_million_characters` не сохранилось в отфильтрованном выводе: верхняя граница стоимости неизвестна. POST было ноль; дополнительные GET/POST требуют отдельного разрешения владельца и документированного потолка (см. `docs/reports/2026-10-01-s06-paid-sync-response.md` в репозитории). Ни один кандидат не включён в стабильный каталог `list`; попытка Gemini speech-parts отклоняется с `BLOCKED_PROVIDER_CONTRACT` (exit `30`) до чтения ключа и POST. Наличие ключа не открывает этот маршрут.
- **Непустая per-part инструкция (`--vibe`) fail-closed** на любом неподтверждённом маршруте: приложение не отправляет инструкцию, которую провайдер прочитает вслух.
- **Оплаченный результат не выбрасывается.** В нативном маршруте `polza-tts` `/audio/speech` приватное тело ответа и receipt сохраняются до разбора и декодирования, поэтому `history resume`/`sync` переигрывают то же наблюдение локально без второго POST; при неоднозначном исходе попытка остаётся, а новый POST не отправляется автоматически.
- **`--overwrite` — платное решение владельца**: удаление оплаченного аудио требует явного `--confirm-delete-paid-audio`, а каталог, которым уже владеет оплаченный прогон, отклоняет свежий writer до удаления и запроса.

Любой реальный запрос к провайдеру — это оплата и отдельное согласие владельца. Справка ничего не отправляет.
