## `generate --resume`

Продолжает прерванный прогон в той же папке, не пересоздавая готовые части.

- `--resume` и `--overwrite` взаимоисключающие: resume продолжает, overwrite сначала удаляет.
- Повторный запуск без обоих флагов на существующем каталоге завершается ошибкой, а не молчаливой перезаписью.
- `--skip-existing` только сообщает, что каталог уже есть, и ничего не генерирует.

```bash
voiceover generate --provider polza-chat-audio --script in/script.md --run-id demo --json --resume
voiceover status --run-id demo --json
```

## `status` — единственная безопасная проверка

`voiceover status --run-id demo --json` показывает `completed_chunks`, `next_chunk`, наличие полного аудио и таймингов, а также `can_resume` и `resume_block_reason`. Ничего не отправляет и не меняет.

## `history resume` и `history sync`

Оба восстанавливают один committed нативный прогон из его снимка и **не перечитывают исходный сценарий**.

| Верб | Что делает | Сеть и деньги |
|---|---|---|
| `history resume UUID` | дозапускает неотправленную часть в обычном порядке | возможен новый платный POST; нужен отдельный допуск |
| `history sync UUID` | сообщает сохранённое состояние, пересобирает JSON-экспорт завершённого прогона, локально восстанавливает часть из проверенного raw | нового POST нет; для известного remote id **возможен GET к провайдеру**, его сеть/тариф нельзя считать автоматически бесплатными или разрешёнными |

```bash
voiceover history resume 11111111-1111-1111-1111-111111111111 --json
voiceover history sync   11111111-1111-1111-1111-111111111111 --json
```

Оба верба принимают только внутренний UUID, не создают новую запись прогона и не принимают `--overwrite`. Изменённый provider/model/voice/текст/порядок/trim-политика отклоняются до провайдера. Если владелец разрешил лишь офлайн-осмотр, используйте `history list/show/costs`, а не `resume`/`sync`.

## Чего приложение не делает

- Не повторяет платный POST автоматически: незавершённая попытка остаётся маркером, а `history sync` для неотправленной части fail-closed с фиксированной ошибкой.
- Не удаляет оплаченное аудио: `--overwrite` требует отдельного `--confirm-delete-paid-audio`, и для каталога, которым владеет оплаченный прогон, свежий writer отказывает с `PAID_TIMING_OUTPUT_OWNED` до удаления, чтения ключа и POST.
- Не восстанавливает orphan-аудио без доверенного состояния: снимок и identity проверяются, иначе прогон не реконструируется.
