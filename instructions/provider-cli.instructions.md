# Provider and CLI contract

- Treat `docs/agent-cli-contract.md` and executable tests as the public compatibility contract; reconcile either with implementation when behavior changes.
- Preserve machine mode: `--json` writes one parseable JSON object to stdout, diagnostics go to stderr, and semantic exit codes remain stable unless an intentional breaking change is approved and documented.
- Resolve a runtime credential through one documented precedence: a non-empty process environment variable wins without reading an env file, then an explicit global `--env-file` validated by metadata as a regular file, then `<call-time CWD>/.env` for compatibility; never search parent directories and never capture an import-time path. An explicit env file replaces the working-directory file instead of merging with it, its contents are not read when the process value wins, and a missing, non-regular, or metadata-inaccessible explicit path fails closed at credential lookup with one redacted path-free message and exit 20 even when the process already holds a usable key. Unreadable or undecodable file contents fail closed only when no process key wins, because that is the only time contents are read. `help` reads no key or env file and does not validate an explicit path; `doctor` may report key presence and the resolved env-file path but never a value.
- Serve `help` only from packaged Markdown resources: `voiceover help [TOPIC] [--raw|--json]` needs no working directory, repository, env file, key, provider, history database, or network; `--json` stays exactly one object and `--raw` prints the packaged Markdown verbatim without frontmatter or ANSI. Topic names are strict lowercase dotted identifiers, so an invalid or unknown topic is a path-free usage error (exit 2, `HELP_INVALID_TOPIC`/`HELP_UNKNOWN_TOPIC`) and an inconsistent packaged help directory is exit 30 `HELP_RESOURCE_ERROR`. Help and the machine contract state stable facts and point readers at parser metadata and the `list` commands for current provider, model, and flag values instead of copying exhaustive lists.
- Let `search` take its mode from an explicit `--mode` when given, otherwise from the non-secret `settings.toml` `[search] default_mode`; an invalid or unreadable consulted settings file fails closed with one path-free `SEARCH_SETTINGS_INVALID` (exit 2) before any database, model, or provider work, while an explicit `--mode` still wins. A configured `semantic`/`hybrid` default is accepted by the settings reader and refused by the command with `SEARCH_MODE_DEFERRED` (exit 2) before opening or creating the database; only FTS5 lexical search is implemented, and the embedding backends belong to the deferred next-release plan.
- Validate provider/model/voice combinations and destructive output paths before requests or filesystem deletion. An explicit `--vibe` is supported only with `generate --text` (or authored inside a `speech-parts` YAML); reject it on legacy script formats before key access or a paid request rather than silently dropping the direction.
- Provider additions or changes must cover registration/listing, defaults, required-key detection, request/response mapping, failures, cost metadata where available, CLI docs, and mocked tests.
- Tests must mock provider/network calls. Never use real keys, paid requests, live endpoints, or user `.env` data.
- Local `transcribe`, `timings`, and `verify-tts` record their observed evidence in the canonical history by default: one run and one attempt, the source audio as an external path/size/SHA-256 rather than a copy, and private transcript roles that never overwrite the source script or the expected TTS text. A history write that fails after a successful provider response keeps that response, reports a fixed persistence failure code, and never claims a save or calls the provider again. A cloud timing or ASR route is admitted only when its paid-submit contract is confirmed: the confirmed `timings --timing-provider groq-whisper|xai-stt` route validates a readable regular source, commits an operation-identity plus `submitting` attempt marker under the canonical history bound to the canonical output root (not the generated history UUID) before its multipart POST, writes a bounded private receipt then the bounded private raw response body (both fsynced) before parsing, and records the transcript and timing artifacts atomically after the response; the attempt keeps an unknown cost and invents no remote id. Ownership is bound to the canonical output root under the shared run lock: every fresh `timings` invocation or `--overwrite` against an already-paid-owned root (still `submitting` or `completed`) fails closed with `PAID_TIMING_OUTPUT_OWNED` before any deletion, key access, or POST, a deliberately different `--run-id`/output dir is a separate paid decision, and `history resume`/`sync` use the run's UUID. Ownership is resolved by an exact, untruncated `run_root` plus paid-origin lookup (never a bounded newest-N scan), a missing descriptor still yields to the committed row, and an unreadable, foreign, newer, ambiguous, or otherwise unusable history database fails closed instead of being treated as unowned (a genuinely empty database the read-only gate validated is a fresh store with no owner, not an unusable one). Because every writer shares the one canonical root namespace, the guard is two-way under the same run lock: `generate` (native or legacy) refuses a paid-owned root and its descriptor, committed row, or raw evidence before selection, deletion, key access, or POST, the native admission re-checks the committed paid owner under that lock before its generation logger creates the run root, so a paid row whose descriptor write failed still refuses a fresh writer, both the local and the cloud `timings` route hold that same lock across the ownership check, deletion, and publication, and the `timings` route likewise refuses a native-history-owned root. A failed or unconfirmed POST leaves the attempt `submitting`, no automatic retry, resume, or sync may issue a second POST, an explicit resume reconciles a crash-window receipt+body pair for the same attempt or a saved raw body replays locally (both with no second POST), and the route refuses before any request when history is disabled (`PAID_TIMING_HISTORY_REQUIRED`). Reconciliation accepts zero or exactly one stored raw artifact and every replay validates that same artifact's attempt, managed path, mandatory size, and digest against the body — never a first-row pick. `history resume`/`sync` read paid state only through the read-only consistent history view (no migration, journal switch, or new sidecar): a WAL without a reusable shared-memory index is refused rather than opened (a read never creates a sidecar), and the run/attempt/artifact reads share one explicit deferred read transaction so an interleaved writer commit cannot tear the view. A corrupt or incompatible database is a fixed error rather than an unknown UUID, and a changed or missing source or an unsafe, symlinked, or retargeted output destination fails closed before parse, probe, or publication. The same confirmed boundary serves two more routes: the integrated cloud timing step (`generate --with-timings --timing-provider groq-whisper|xai-stt`) commits its one paid attempt and private raw body into a deterministic child root `.paid-timing` inside the parent native run root and publishes `<prefix>.timings.json`/`.srt` into the parent root, and the per-turn cloud dialogue QA (`--tts-quality-provider xai-stt`) commits one paid attempt and private raw body per turn into a deterministic child root `.paid-quality/<turn>` and links the observed PASS/FAIL verdict plus private `verification_transcript` to the parent turn before concat and before the next paid turn; the parent native root is never overwritten by a child, a parent-foreign `--timings`/`--tts-quality-provider` request is only admitted on the eligible native TTS/dialogue routes, and `openrouter-whisper` (no real timestamps), a cloud quality provider on a non-dialogue route, and every other cloud ASR route stay legacy until their own paid-submit contract is confirmed.
- Persist ASR transcript timing only with its observed origin, effective model identity, canonical text-source UUID, exact source-text hash, and real integer-ms word/segment bounds. A long-form result's final source-audio hash must match the history source artifact before a run is saved. External long-form chunk coverage is technical evidence, never a substitute for acoustic speech timestamps. A derived search range may be attached only to that exact canonical ASR transcript UUID and hash, and only when every speech character in the search chunk has an observed span; partial, mismatched, imported, and text-only sources retain NULL timing. Offline rebuilds must reproduce the same ranges from SQLite alone, without model or network access.
- Prefer resumable generation and existing-output safeguards. Do not use overwrite for paid generation unless the user explicitly chooses that loss/cost risk.
- On the paid cloud `timings --timing-provider groq-whisper|xai-stt` route, handle the credential-free existing-output refusal and `--skip-existing` report first, then resolve the provider key (`GROQ_API_KEY`/`X_AI_API_KEY`) under the already-held output-root lock, and only then let `--overwrite` delete the output root or reserve the paid attempt; an unusable credential therefore leaves the output root intact and writes no false `submitting` marker, reporting the fixed redacted credential failure with exit 20.
- For paid TTS, persist an attempt marker before submit and preserve it as evidence until the outcome is confirmed and the part is saved. Never automatically resubmit an unconfirmed attempt via outer retry, provider fallback, resume, or overwrite; keep local-provider retry separate. For a paid Polza TTS ElevenLabs `/media` submit, a stored bounded accepted task id may be finished by an explicit `--resume` with GET poll/download only — never a second POST — while provider, model, voice, and script identity still match and every earlier chunk file is on disk; `--overwrite` stays blocked for any marker. An ordinary non-dialogue `polza-chat-audio` submit has the same synchronous inline-audio shape as `openrouter-tts`: it is one streaming submit with no recoverable task id and its cost stays unknown rather than invented; its resolved compatibility `--fallback-voice` is recorded as a non-secret identity input so a resume with a changed value is refused, and the provider never sends an automatic fallback request.
- Preserve accepted paid audio in a run-local raw file with a bounded receipt before FFmpeg. A matching on-disk receipt may resume local conversion without another provider request; a missing or corrupt receipt never permits a fresh paid submit (a separately valid Polza Media task id may still recover by GET only). Retain paid raw after success rather than treating it as disposable cache.
- For an admitted native synchronous `polza-tts` `/audio/speech` submit, persist a bounded private HTTP body and receipt bound to the reserved attempt, part, synthesis fingerprint, provider/model/voice, and requested response format **before** status checking, JSON parsing, or audio decoding. On resume, verify and replay that same response locally before raw-only reconciliation even if decoded raw already exists, so an observed cost is not discarded; invalid or partial evidence blocks without another POST/GET. Only pre-feature attempts with no response evidence may use the older decoded-raw-only recovery with unknown cost. This rule does not imply a stable Gemini route or alter the legacy executor.
- Admit `polza-tts` `google/gemini-3.8-flash-tts` with `speech-parts` only behind the explicit experimental CLI opt-in; keep the default route and Flash-Lite fail-closed and the model outside the stable catalog. Each authored part has one scalar `voice` and its own paid POST; transmit its effective direction only in a separate `instructions` field, never in the spoken `input`. That Gemini field is undocumented, so an opt-in is not evidence of stable audible behavior, two voices in one POST, or an external invoice. Record the opt-in in the native snapshot; `generate --resume` must match it, while `history resume`/`sync` replay the committed policy and never repeat an unconfirmed paid submit. The existing paid marker, raw-before-parse, bounded receipt, no-redirect and no-auto-retry safeguards remain mandatory.
- Once a run has committed native ownership or carries native local evidence (ownership descriptor, `native_history` run state, or a raw receipt), never fall back to the legacy JSON writer; serialize ownership selection and mutation of both native and legacy writers under the shared run-root lock, and write JSON only as a DB-derived compatibility export for native runs.
- An admitted native run records its own output-processing semantics: `--no-trim` or the default trim is stored with the run so a resume refuses a changed flag before any provider, and each converted part is trimmed only when the recorded setting says so.
- An admitted native run may request the recorded trim and either or both integrated steps: `--with-timings` for the local `faster-whisper` or the paid cloud `groq-whisper`/`xai-stt` provider, and/or a quality provider that is either an installed local `--tts-quality-provider` (`qwen-local`/`nemotron-local`) or, on the two admitted dialogue routes only, the paid cloud `xai-stt`. Either request's effective settings are recorded with the run's output options so a resume refuses changed options before any provider; a local model's availability, or a cloud provider's key, is preflighted before a new paid TTS POST and no implicit download is allowed. The linked result is written as its own history run linked by `parent_uuid` (`timings`, or `verify` with a private `verification_transcript` and no stored expected text), never as fabricated TTS parts or a legacy finalizer/JSON write. A step failure keeps the completed TTS audio, paid raw bytes, and cost, removes any just-written unlinked artifact, and reports a fixed partial error; an explicit `generate --resume` or `history resume` retries only the missing local step with no TTS POST/GET, while `history sync` runs no local model and reports the step incomplete. A quality mismatch keeps the paid audio and cost, records the observed failure through the same linked `verify` run (`quality_passed: false`, no stored expected text) before returning the existing quality exit code, and re-reports that persisted verdict on a later resume or `history sync` with no second local model run; a linked-history persistence failure reports the fixed partial error instead of claiming a stored verdict; an unregistered quality provider, and a cloud quality provider on a non-dialogue route, stay on the legacy route. The one admitted native dialogue route (`openrouter-tts` Gemini, two cast voices, required installed local or paid cloud `xai-stt` `--tts-quality-provider`) instead verifies every turn after its conversion and before the next paid turn and the final concat, and stores each turn's content-free PASS/FAIL verdict and private `verification_transcript` on the TTS run linked to that turn's part; a recorded FAIL is durable, keeps the paid raw bytes, audio, and cost, and is re-reported by `generate --resume`, `history resume`, and `history sync` without a second paid POST or local model run. A second native dialogue route, the `omnivoice-local` preset two-profile bank script, is local: one turn per request with its cast voice-bank profile, a distinct durable cost-free `local_tts_chunk` attempt committed before every real local invocation (`status` and `cost` NULL, never a paid marker) with each turn's raw bytes linked to that attempt before conversion so a crash rebuilds locally with no second model run, a caught or interrupted local invocation whose truthful outcome stays recorded (`local_failed`, or a pending row when the process died) and which stays repeatable on an explicit resume, and a fail-closed refusal before any local model call when a referenced reference is missing or its digest changed; `history costs` counts those real local attempts as `local_attempts_without_api_charge` instead of a cloud unknown or an invented zero, and `history sync` never runs that local model and reports a fixed local no-inference error for an unattempted part. When that dialogue route recorded an installed local `--tts-quality-provider`, it runs the same per-turn local gate before concat, and both dialogue routes also admit the recorded `--no-trim` and an integrated `--with-timings` step for the local `faster-whisper` or the paid cloud `groq-whisper`/`xai-stt` providers, and (for the OpenRouter route's required gate and the OmniVoice route's optional gate) the paid cloud `xai-stt` quality provider. The same admitted `omnivoice-local` family also covers the ordinary non-dialogue `--mode preset --voice-bank` monologue: its whole script merges into one session part that clones the one selected bank profile, it reuses that exact cost-free local attempt/raw seam, and its snapshot identity records the catalog locator, the mode, the selected profile's reference locator/digest/text and language, the model, and the effective voice. The ordinary non-dialogue `auto`, `clone`, and `design` OmniVoice modes merge into that same one-session local call and each record their own snapshot identity (the mode, the model, the mode marker as the effective voice, and, for clone, the reference locator/digest/size and exact reference text, or, for design, the exact instruction); a committed reference that is missing or changed fails closed before any local model, and `--mode auto` leaves voice selection to the runtime and substitutes no preset. A non-dialogue `format: voiceover` script is admitted for the ordinary polza/openrouter/chat-audio route, for every admitted ordinary non-dialogue `qwen-local` mode, and for the `omnivoice-local` preset bank route: the voiceover validator resolved one provider, model, and voice for the whole script, so no per-chunk provider or voice is invented. The `qwen-local` `preset` mode keeps that validated voice, while `clone`/`design` replace it with their mode marker exactly as the legacy executor does, so the committed identity is the route's real one and no new voice semantics is introduced. The `omnivoice-local` preset bank route's only validator-permitted voice is the default bank marker, which the admitted catalog must resolve into the run's committed profile identity; a non-preset OmniVoice mode always rejects the voice such a script supplies, so that combination stays a usage error, and the `qwen-local` `--mode auto` choice is not implemented and is rejected as a usage error before any provider. A third admitted native local route family, the ordinary non-dialogue `qwen-local` modes (clone with a reference sample, and the instructed `preset`/`design` modes), reuses the same cost-free `local_tts_chunk` attempt/raw seam; it records its local identity in the snapshot (the clone reference locator, digest, and size, the reference text, or the instructed mode's model/voice and exact instruction), preflights the installed runtime and its cached model and, for clone, the reference sample before the first local model call with no implicit download, and its `history sync` reports the same fixed local no-inference error for an unattempted part. Every other dialogue route stays on the legacy executor.
- `history resume UUID` and `history sync UUID` reconstruct one committed native TTS run from its stored snapshot (never re-reading the original script) and reuse that same run lock, CAS reservation, and executor. `history resume` may submit a truly unattempted part, so it is potentially paid. `history sync` must never start a new paid submit: it may only rewrite the DB-derived compatibility JSON of a completed run, rebuild a part locally from verified raw evidence, or finish a known remote id with GET-only, and it must fail closed with a fixed error before any key or provider for an unattempted part or an unconfirmed submit. A confirmed paid timing run is handled by the same verbs without a provider: `history sync` reports its durable state and `history resume` replays its saved raw response body locally (never a second POST), or fails closed with `PAID_SUBMIT_UNCONFIRMED` while the attempt is `submitting`. The same verbs reconstruct a parent native run's pending integrated cloud timing and per-turn cloud quality work from its recorded output options, replay already-saved raw bodies locally, and block on any unconfirmed submit with no second POST. Neither verb may create a new run row or create the database for an unknown or legacy UUID, and `--overwrite` is never accepted for them.
- Do not promise current model availability, price, latency, or quality from historical examples; label snapshots and verify current facts only with approved network access.
