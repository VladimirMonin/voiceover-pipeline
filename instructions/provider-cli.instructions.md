# Provider and CLI contract

- Treat `docs/agent-cli-contract.md` and executable tests as the public compatibility contract; reconcile either with implementation when behavior changes.
- Preserve machine mode: `--json` writes one parseable JSON object to stdout, diagnostics go to stderr, and semantic exit codes remain stable unless an intentional breaking change is approved and documented.
- Validate provider/model/voice combinations and destructive output paths before requests or filesystem deletion.
- Provider additions or changes must cover registration/listing, defaults, required-key detection, request/response mapping, failures, cost metadata where available, CLI docs, and mocked tests.
- Tests must mock provider/network calls. Never use real keys, paid requests, live endpoints, or user `.env` data.
- Local `transcribe`, `timings`, and `verify-tts` record their observed evidence in the canonical history by default: one run and one attempt, the source audio as an external path/size/SHA-256 rather than a copy, and private transcript roles that never overwrite the source script or the expected TTS text. A history write that fails after a successful provider response keeps that response, reports a fixed persistence failure code, and never claims a save or calls the provider again. A cloud timing or ASR route stays legacy until its paid-submit contract is confirmed.
- Prefer resumable generation and existing-output safeguards. Do not use overwrite for paid generation unless the user explicitly chooses that loss/cost risk.
- For paid TTS, persist an attempt marker before submit and preserve it as evidence until the outcome is confirmed and the part is saved. Never automatically resubmit an unconfirmed attempt via outer retry, provider fallback, resume, or overwrite; keep local-provider retry separate. For a paid Polza TTS ElevenLabs `/media` submit, a stored bounded accepted task id may be finished by an explicit `--resume` with GET poll/download only — never a second POST — while provider, model, voice, and script identity still match and every earlier chunk file is on disk; `--overwrite` stays blocked for any marker. An ordinary non-dialogue `polza-chat-audio` submit has the same synchronous inline-audio shape as `openrouter-tts`: it is one streaming submit with no recoverable task id and its cost stays unknown rather than invented; its resolved compatibility `--fallback-voice` is recorded as a non-secret identity input so a resume with a changed value is refused, and the provider never sends an automatic fallback request.
- Preserve accepted paid audio in a run-local raw file with a bounded receipt before FFmpeg. A matching on-disk receipt may resume local conversion without another provider request; a missing or corrupt receipt never permits a fresh paid submit (a separately valid Polza Media task id may still recover by GET only). Retain paid raw after success rather than treating it as disposable cache.
- Once a run has committed native ownership or carries native local evidence (ownership descriptor, `native_history` run state, or a raw receipt), never fall back to the legacy JSON writer; serialize ownership selection and mutation of both native and legacy writers under the shared run-root lock, and write JSON only as a DB-derived compatibility export for native runs.
- An admitted native run records its own output-processing semantics: `--no-trim` or the default trim is stored with the run so a resume refuses a changed flag before any provider, and each converted part is trimmed only when the recorded setting says so.
- An admitted native run may request the recorded trim and either or both integrated local steps: `--with-timings --timing-provider faster-whisper` and/or an installed local `--tts-quality-provider` (`qwen-local`/`nemotron-local`). Either request's effective settings are recorded with the run's output options so a resume refuses changed options before any provider; local model availability is preflighted before a new paid TTS POST and no implicit download is allowed. The linked result is written as its own history run linked by `parent_uuid` (`timings`, or `verify` with a private `verification_transcript` and no stored expected text), never as fabricated TTS parts or a legacy finalizer/JSON write. A step failure keeps the completed TTS audio, paid raw bytes, and cost, removes any just-written unlinked artifact, and reports a fixed partial error; an explicit `generate --resume` or `history resume` retries only the missing local step with no TTS POST/GET, while `history sync` runs no local model and reports the step incomplete. A quality mismatch keeps the paid audio and cost, records the observed failure through the same linked `verify` run (`quality_passed: false`, no stored expected text) before returning the existing quality exit code, and re-reports that persisted verdict on a later resume or `history sync` with no second local model run; a linked-history persistence failure reports the fixed partial error instead of claiming a stored verdict, and a cloud or unregistered quality provider stays on the legacy route. The one admitted native dialogue route (`openrouter-tts` Gemini, two cast voices, required installed local `--tts-quality-provider`) instead verifies every turn after its conversion and before the next paid turn and the final concat, and stores each turn's content-free PASS/FAIL verdict and private `verification_transcript` on the TTS run linked to that turn's part; a recorded FAIL is durable, keeps the paid raw bytes, audio, and cost, and is re-reported by `generate --resume`, `history resume`, and `history sync` without a second paid POST or local model run. A second native dialogue route, the `omnivoice-local` preset two-profile bank script, is local: one turn per request with its cast voice-bank profile, a distinct durable cost-free `local_tts_chunk` attempt committed before every real local invocation (`status` and `cost` NULL, never a paid marker) with each turn's raw bytes linked to that attempt before conversion so a crash rebuilds locally with no second model run, a caught or interrupted local invocation whose truthful outcome stays recorded (`local_failed`, or a pending row when the process died) and which stays repeatable on an explicit resume, and a fail-closed refusal before any local model call when a referenced reference is missing or its digest changed; `history costs` counts those real local attempts as `local_attempts_without_api_charge` instead of a cloud unknown or an invented zero, and `history sync` never runs that local model and reports a fixed local no-inference error for an unattempted part. When that dialogue route recorded an installed local `--tts-quality-provider`, it runs the same per-turn local gate before concat, and both dialogue routes also admit the recorded `--no-trim` and an integrated local `--with-timings --timing-provider faster-whisper` step. The same admitted `omnivoice-local` family also covers the ordinary non-dialogue `--mode preset --voice-bank` monologue: its whole script merges into one session part that clones the one selected bank profile, it reuses that exact cost-free local attempt/raw seam, and its snapshot identity records the catalog locator, the mode, the selected profile's reference locator/digest/text and language, the model, and the effective voice. The ordinary non-dialogue `auto`, `clone`, and `design` OmniVoice modes merge into that same one-session local call and each record their own snapshot identity (the mode, the model, the mode marker as the effective voice, and, for clone, the reference locator/digest/size and exact reference text, or, for design, the exact instruction); a committed reference that is missing or changed fails closed before any local model, and `--mode auto` leaves voice selection to the runtime and substitutes no preset. A non-dialogue `format: voiceover` script is admitted for the ordinary polza/openrouter/chat-audio route, for every admitted ordinary non-dialogue `qwen-local` mode, and for the `omnivoice-local` preset bank route: the voiceover validator resolved one provider, model, and voice for the whole script, so no per-chunk provider or voice is invented. The `qwen-local` `preset` mode keeps that validated voice, while `clone`/`design` replace it with their mode marker exactly as the legacy executor does, so the committed identity is the route's real one and no new voice semantics is introduced. The `omnivoice-local` preset bank route's only validator-permitted voice is the default bank marker, which the admitted catalog must resolve into the run's committed profile identity; a non-preset OmniVoice mode always rejects the voice such a script supplies, so that combination stays a usage error, and the `qwen-local` `--mode auto` choice is not implemented and is rejected as a usage error before any provider. A third admitted native local route family, the ordinary non-dialogue `qwen-local` modes (clone with a reference sample, and the instructed `preset`/`design` modes), reuses the same cost-free `local_tts_chunk` attempt/raw seam; it records its local identity in the snapshot (the clone reference locator, digest, and size, the reference text, or the instructed mode's model/voice and exact instruction), preflights the installed runtime and its cached model and, for clone, the reference sample before the first local model call with no implicit download, and its `history sync` reports the same fixed local no-inference error for an unattempted part. Every other dialogue route stays on the legacy executor.
- `history resume UUID` and `history sync UUID` reconstruct one committed native TTS run from its stored snapshot (never re-reading the original script) and reuse that same run lock, CAS reservation, and executor. `history resume` may submit a truly unattempted part, so it is potentially paid. `history sync` must never start a new paid submit: it may only rewrite the DB-derived compatibility JSON of a completed run, rebuild a part locally from verified raw evidence, or finish a known remote id with GET-only, and it must fail closed with a fixed error before any key or provider for an unattempted part or an unconfirmed submit. Neither verb may create a new run row or create the database for an unknown or legacy UUID, and `--overwrite` is never accepted for them.
- Do not promise current model availability, price, latency, or quality from historical examples; label snapshots and verify current facts only with approved network access.
